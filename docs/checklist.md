## 第 0 步 · 判定对象识别（claim 分类决策树）【表内】

**分类对象是 `claim_id`（一条声称），不是论文。** 一篇论文有几条声称，就分别分类、分别成行。按 Q0.0 → Q0.3 的顺序问，答案落到某一类就停。

- **Q0.0** 这条声称是经验性的吗？也就是作者有没有在数据上**算出一个新的对齐数字**。**否**（综述、Perspective、理论论证，或只引用别人的数字）→ **X：移出**。**是** → 问 Q0.1。
- **Q0.1** 这个数字是不是「在训练数据上拟合映射、再在留出数据上评估」得到的？**否** → **B**（RSA、RDM 相关、CKA 等不拟合映射的几何比较）。**是** → 问 Q0.2。
- **Q0.2** 映射是不是「模型特征 → 脑响应」的**编码**方向，而且分数衡量的是预测响应与实测响应的一致程度（Pearson r、R²、解释方差，或它们除以 ceiling 后的值）？**否**：映射是「脑响应 → 刺激特征 / 标签」的**解码**方向，或者分数是分类 / 识别 / 排序精度（含 2v2、rank accuracy）→ **D**。**是** → 问 Q0.3。
- **Q0.3** 声称说的是**某一个模型**（或它相对基线）的分数有多高吗？**是** → **A**。**否**：说的是分数怎样随模型侧变量（size、层、训练步数 / 是否训练、语言能力）或脑侧变量（时滞、ROI）变化 → **C**。

例：S1 → A；C1 主声称（compositional R=0.048）→ A；C1 副声称（brain score × 语言能力 R=0.57）→ C；E1（size↔编码性能）→ C；T1（lag-layer r=0.85）→ C；I1（RSA）→ B；Pereira 2018 universal decoder（脑 → 语义向量）→ D（注册表里它是数据源 / 基线，不审计）；N1（Nastase et al. 2026 Neuron Perspective）→ X。

**各类的固定处理**

- **X**：不走后续步骤，不进判定表的「被审计声称」行。只在注册表记一行「移出：非经验性」并写明理由。
- **B / C / D**：第 1–3 步照做。八要素、切分、前提与混淆核验跟声称类型无关，必须填；B 类第 2 步填「N/A：无 train/test 切分」。跳过第 4–5 步，判定 = **无法判定（协议不适用：B）**，C、D 同样写法。「缺什么」固定写两项：① 本协议版本没有该类的判定规则；② 第 1–3 步发现的其它缺口。不得把 A 的 Δr 规则套到 B/C/D 声称上，比如只拿 E1 的最大模型跑一遍 A 管线：得出的判定跟 scaling 声称无关。
- **A**：走完第 1–6 步。

> 范围说明：**A 是代码的原生路径**（`judge.py` 的 P1–P5 全按回归 Δr 口径写）；**B/C/D 尚未进代码**。v0.2 已定：只补检查表文字，B/C/D 的判定规则等数据加载器到位再排进后续里程碑。C 的最小规则在「某个 C 类声称的数据有了加载器」时实现，最近的候选是 E1 的播客 ECoG；B、D 在「某个该类声称的数据和代码公开」时立项。

v0.3 补充（不改上面三档）：

## 第 3 步 · 前提与混淆核验（P2–P5、混淆基线、层选择、诊断项）

### 3.1 P2 · 显著性 null

- 【代码】`null_test.method` 只能取 `circular_shift`。`iid / permutation / shuffle / iid_permutation` 会被 `validate()` 直接拒绝，理由是 i.i.d. null 破坏 BOLD 自相关，会虚报显著性（`config.py:28, 137–143`）。判定用的是 Δ 的循环移位 p（行字段 `p_delta`）。
- 【表内·②】论文自报时，P2 过 ⟺ 报告的显著性来自**保留响应时间自相关**的 null，也就是特征与响应之间的循环时移或相位随机化。逐样本 / 标签置换、i.i.d. 置换都不算过。代码只实现了循环移位；② 也接受相位随机化，因为 P2 要的是「保留自相关」，两者都满足。

### 3.2 P3 · 零输入消融（P3 只有这一项）

- 【代码】P3 过 ⟺ **|r(全零输入) / r(真实输入)| < 0.10**。两个 r 都先在各被试内对体素取均值，再对被试取均值，最后相除（`pipeline.py:82, 115–117`；`judge.py:70–74`；阈值 `judge.max_zero_input_retained = 0.10`）。真实 r = 0 时比值无定义，也算不过。**这里比的是保留比例，不是 |r| < 0.10（v0.2 写错了）。**
- 不过 → **无法判定**（「预测不依赖输入，管线可疑」）。
- 这一项检验管线本身是否有效：线性读出遇到全零输入只会给出常数预测，r 应为 0。如果分数保住了，说明预测里混进了不该有的信息，比如由 Y 构造出来的预测（`baselines.py` 的 `zero_input_ablation` 说明）。
- 【表内·②】论文没报零输入（或常数输入）消融 → P3 记「缺」→ 无法判定。

**裁决（评审意见 #1）：未训练 / 随机权重模型不是 P3 的一部分，不是 P1–P5 中的任何一条，也不属于「混淆已控制」。**
- 依据：`decide()` 只读 `res["zero_input"]["all"]`（`judge.py:70`）。全仓检索 untrained / random weight，判定路径里没有相关代码。`activations.py` 里出现的 untrained 指的是合成后端的玩具 LM，与判定无关。
- 理由：零输入检验管线是否有效，期望值是确定的（0）。未训练模型本身带有真实的刺激信息（词嵌入、位置、架构的归纳偏置），分数高并不说明管线坏了，也找不出一个说得过去的阈值。至于「训练重不重要」，那是另一条声称，按 Q0.3 归 C 类。
- 读法：只填进诊断栏（3.7），写「未训练分数 / 训练后分数」及出处，不改判定。S1：Schrimpf 正文 Fig 5 报告未训练 GPT2-xl 在三套数据上平均约 51% 归一化预测力，比训练后低约 20%（PMC 正文已核）。这个数进 S1 的诊断栏，不影响 S1 的标签。

### 3.3 P4 · 测试块数

- 【代码】**block = 数据加载器给每个样本标的 `block_ids`**，即「绝不能跨 train/test 边界」的最小单位：句子类数据是**段落**（Pereira2018 每段 3–4 句），听故事类数据是**故事**（`data.py:1–9, 29`）。
- 【代码】P4 数的是**整个数据集里不同 block 的个数**（`len(np.unique(block_ids))`，`pipeline.py:122`）。**不是折数，也不是每折含几个 block。** contiguous 切分下每个 block 恰好当一次测试块，所以「测试块数」就是 block 总数。P4 过 ⟺ block 数 ≥ 10（`judge.min_test_blocks`）。
- S1：96 段 ≥ 10，过。S1 用的是 8 折，折数与 P4 无关。
- 【代码】块 bootstrap 的重采样单位就是这个 block：`bootstrap.unit` 只能取 `block`（`config.py:150–151`），绝不逐体素。
- 【表内·②】数原文留出的段落 / 故事个数。只有一个连续故事的数据（E1、T1 的 30 分钟播客）block 数 = 1，P4 不过。把一个故事切成子段当 block 不在 v0.3 范围内，要这样做须先在协议里规定切法。代码对这种数据同样跑不了：block 数少于折数时会报错（`splits.py` 的 `_contiguous_folds`）。

### 3.4 P5 · null 的分辨力

- 【代码】最小可达 p = 1 / (循环移位个数 + 1)（`null.py:74`）。P5 过 ⟺ 最小可达 p ≤ α = 0.05，也就是至少 19 个有效移位。S1：369 个移位，最小可达 p = 0.0027，过。
- 【表内·②】用论文报告的 null 次数 n 计算，要求 1/(n+1) ≤ 0.05。

### 3.5 混淆基线（「混淆已控制」的唯一定义）

- 【代码】**混淆已控制 ⟺ 判定行 `baselines_enabled = true` ⟺ 配置里 `baselines.enabled: true` 且 `baselines.confounds` 非空**（`pipeline.py:51`）。可选项只有两项：`position`（样本在所属 block 内的位置，短 block 用 one-hot，长 block 用 10 等分箱）和 `word_rate`（每秒词数；呈现时长固定时就是句长）（`config.py:77–83`、`CONFOUNDS`；`baselines.py`）。协议配置默认两项都开。
- 混淆已控制时，判定量是 **Δ = r(LLM + 混淆) − r(混淆)**；未控制时只有 r_LLM。
- **未控制混淆 → 封顶**：不能判「仍成立」，但仍可判「不成立」（条件是 r_LLM 的 CI 上界 < SESOI），其余情况都是无法判定。封顶**不是**硬前提，单凭它不会得出「无法判定」。
- null（3.1）和零输入（3.2）**不属于**混淆控制。它们是 P2、P3，不满足时直接「无法判定」，比封顶更重。OASM、词频、未训练模型也不属于混淆控制，它们是诊断项（3.7）。
- 【表内·②】混淆已控制 ⟺ 原文报告了 LLM 相对某个基线模型的增量，且该基线模型至少含位置或语速（句长）中的一项。增量可以是联合模型减基线模型，也可以是等价的方差分解；原文还必须给出这个增量的 CI。

### 3.6 层选择（原「坑 #2」，v0.3 起有明确后果）

**① 本管线复跑【表内】**：判定行必须来自 `model.layer_selection: nested` 的运行，这是默认设置：层在内层折上选，从不看外层测试折（`config.py:58`）。`fixed` 的运行要同时满足两条才能当判定行：一是 `fixed_layer` 事先登记过，即含该值的配置所在 commit 早于判定行的 `timestamp`；二是这个层不是从本数据的外层测试分数里挑出来的，只能是事先指定，或在另一数据集 / 另一实验上选出。先从本次运行的 `layer_curve.json` 取 argmax、再拿这层跑一次 `fixed`，这样的运行只能作描述性对照（对齐原文口径），不能当判定行。S1 计划中的「argmax 重算」就属于这种情况。代码不检查这一条，见「需要改代码的项」第 2 项；判定行里已有 `layer_selection` 列，评审者可以照此手工执行。

**② 论文自报【表内】**：按原文做法归入下面三类之一。

- **L-a** 层在评分数据之外选定（嵌套 / 交叉验证选层、在另一实验或数据集上选、事先指定）→ 没有后果。例：I1 用交叉验证选层（I1 本身归 B）。
- **L-b** 在评分数据上取 argmax，但原文给了一个对照：选层的数据与评分的数据不重叠，且两种选法的分数差，其误差棒 / CI 含 0 → 没有后果，行内记「test-argmax + 原文对照（出处）」。这个对照只能说明选层偏差小，**不能顶替 P1**。
- **L-c** 在评分数据上取 argmax，又没有 L-b 那样的对照 → **封顶**，与 3.5「未控制混淆」同型：不能判「仍成立」，仍可判「不成立」。理由：在评分数据上挑最优层只会把分数抬高，抬高后都没过 SESOI，「不成立」的结论依然可信。

**S1 归 L-b（评审意见 #5 核实结果）**：Schrimpf 报告的是每个模型的最优层（argmax），但做了 L-b 型对照。PNAS 正文写的是 "We report the score for the best-performing layer of each model … but control for the generality of the layer choice in a train/test split (SI Appendix, Fig. S2 B and C)"（PMC 版正文已核）。补充图 S2 的图注写明（bioRxiv 2020.06.26.174482 版已核）：在 Pereira2018 实验 3 上，比较「直接在实验 3 上选层」与「在实验 2 上选层」两种分数，差值 "minimal with error bars overlapping 0"；另外各层分数在实验 2 与实验 3 之间相关 r=.95。PNAS 版 SI 的 PDF 本身没拿到（之前下载到的是一个跳转页），它的图注与 bioRxiv 版是否一字不差，**未核**。所以 v0.2 写的「原文未提、我方补入的泄漏」不对，撤回。注意 Schrimpf 的这个对照同样是在 shuffled 切分下做的，所以对 P1 没有帮助。

## 第 4 步 · reference_value 提取（只对 A 类）

- **reference_value = 原文报告的原始分数**，即原文自己那个指标的原始值（raw Pearson r 之类），**不是**除以 ceiling 之后的值，也不是百分比。**S1 = 0.31**，不是「≈100%」，也不是 0.31/0.32。
- 理由：保留率 = r_LLM / reference_value（`judge.py:84`），分子 r_LLM 是本管线的原始 Pearson r，分母必须是同量纲的原始分数。
- 原文只报了归一化值时：
  - 原文同时报了 ceiling → reference_value = 归一化值 × ceiling，`reference_source` 写「由 <归一化值> × <ceiling> 推得，出处 …」；
  - 没报 ceiling → reference_value = null。这时定量部分不判，`claim_scope` 会自动写「参考值未提供」；缺什么写「原文无原始分数」。
- `reference_ceiling` 填原文报的 ceiling，只记录，不进判定，也不进判定行。
- `reference_metric` 必须写全五项口径：**读出**（OLS / 岭 / …）、**切分**（shuffled / contiguous，以及折数）、**聚合**（在体素 / 电极 / 被试上取均值还是中位数）、**层选择**（3.6 的 L-a/b/c）、**ceiling 方法**（如有）。其中任何一项与本管线不同，保留率就只报告，不能设 min_retention（第 5.4 节条件 ③）。本管线的口径是：岭回归；contiguous；体素均值再被试均值；nested 选层。
  - S1 示例：`raw Pearson r；OLS；shuffled 5 折；体素中位数再被试中位数；test-argmax 选层（L-b，Fig S2b,c 对照）；ceiling = 留出被试 + 外推`。现在 YAML 里的字符串少了层选择和 ceiling 两项，见「需要改代码的项」第 6 项。
- 无单一数值（scaling 曲线、关联 r=0.55/0.52 之类）→ 说明这条声称不是 A，回第 0 步。

## 第 5 步 · 判定

### 5.1 数字来源

**数字来源先写清**（否则评审者会卡在「Δr 从哪来」）：判定所用数字要么来自①本管线复跑（写明命令 `scripts/run_d1.py --config configs/<claim>.yaml` 与配置文件），要么来自②论文自报——② 之下 P2/P3 通常缺失，结果多为「无法判定（缺 P2/P3）」，并写明缺哪条。

**来源优先序【表内】**：① 能执行并且已经跑完 → 判定由 ① 决定，② 的结果作为「原文口径」记进注册表，不改判定。① 无法执行 → 判定由 ② 决定，「缺什么」里加一句「① 不可执行：<原因>」。

**① 本管线复跑：第三方需要的全部信息**

- **仓库**：本仓库，命令都在仓库根目录执行。所用代码版本以判定行的 `git_commit` 为准；v0.3 对应内部版本 `9c49cf0`。
- **环境**：`scripts/00_setup_env.sh` 建的 venv，解释器是 `data/venv/bin/python`。2026-10-20 实测版本：Python 3.12.3、numpy 2.5.4、scipy 1.18.1、PyYAML 6.0.3、transformers 5.19.0、torch 2.14.1+cu130；完整清单由 setup 脚本写到 `data/venv/pip-freeze.txt`。只用 CPU，`validate()` 会拒绝非 cpu 设备。HF 模型缓存由 setup 脚本固化为 `data/cache/huggingface`。环境自检命令是 `… scripts/run_d1.py --smoke`，退出码 0 即通过。

  - `block_ids` 中每个 block 是连续的一段，并且是段落或故事（3.3）；

**② 论文自报：逐项怎样算过**

| 项 | ② 下怎样算「过」 |
|---|---|
| P1 | 原文明写 contiguous（block 整块留出，测试折连续），见第 2 步 |
| P2 | 3.1：循环时移或相位随机化 |
| P3 | 3.2：原文报了零输入 / 常数输入消融，保留比例 < 0.10 |
| P4 | 3.3：留出的段落 / 故事 ≥ 10 |
| P5 | 3.4：1/(n+1) ≤ 0.05 |
| 混淆 | 3.5：报告了相对位置 / 语速基线的增量，并给出 CI |
| 层选择 | 3.6：L-a / L-b 没有后果，L-c 封顶 |
| CI | 原文给出 Δ（未控制混淆时给 r_LLM）的 CI，并且 CI 的重采样单位是 block 或被试（含被试 × block 分层）。在体素 / 电极 / 样本上算的 CI 或 t 检验不算。例：E1 的 t=16.791，由 df=159 反推的 p 与原文一致，说明是在 160 个电极上做的检验。不算时记「缺块级 CI」，结果为无法判定 |
| p | Δ 的 p 来自 3.1 认可的 null |

各项核完后，套用 5.3 的同一套顺序。② 下 P2/P3 几乎总是缺，所以结果多为无法判定。这是预期内的结果，不代表评审没做完；想得到仍成立 / 不成立，就走 ①。

### 5.2 协议常量

**α = 0.05；SESOI(Δr) = 0.02（已冻结于 v0.1，不再讨论）；min_test_blocks = 10（block = 段落 / 故事，见 3.3）；零输入保留比例上限 = 0.10（比值，见 3.2）**。Δr = r(LLM+混淆基线) − r(混淆基线)，配对块 bootstrap CI（**bootstrap 单元 = 整段/整故事，绝不逐体素**）+ 循环移位 p。metric 口径 = 体素级 Pearson r（留出段预测，mean over voxels 再 mean over subjects）。

### 5.3 判定顺序（照抄 `decide()`，`judge.py:106–129`，不另立顺序）

按下面 1 → 5 的顺序走，**一旦得出结论就停**：

1. **核 P1–P5**（第 2 步、3.1–3.4）。任何一条不过 → **无法判定（前提不满足：P?）**，到此为止。这时效应再小也不判「不成立」，效应再大也不判「仍成立」。不过的条目要全部写进「缺什么」；代码会先把五条都查完再下判定（`judge.py:66–78`）。
2. **登记封顶项**：未控制混淆（3.5）；② 路径下层选择属 L-c（3.6）。封顶项只是取消「仍成立」这个选项，单凭它不会得出「无法判定」，也不妨碍判「不成立」。
3. **先查「不成立」**。以下任一条成立 → **不成立**：
   - 混淆已控制，且 Δ 的 CI 上界 < SESOI（0.02）；
   - 未控制混淆，且 r_LLM 的 CI 上界 < SESOI；
   - 设了 min_retention，且保留率 CI 上界 < min_retention。
4. **再查「仍成立」**。以下各条全部成立 → **仍成立**：混淆已控制；没有 L-c 封顶；Δ 的 CI 下界 > 0；p_null(Δ) < α；如果设了 min_retention，保留率 CI 下界 ≥ min_retention。
5. **其余情况 → 无法判定（证据不足）**。「缺什么」写明卡在哪一条，比如「Δ 的 CI [a, b] 跨 0 / SESOI，或 p_null(Δ) ≥ α：需要更多被试或测试块」，或「未控制混淆：最多只能判不成立」。

**优先序一句话**：P1–P5 不过（无法判定）＞ 不成立 ＞ 仍成立 ＞ 无法判定（证据不足）。

**几种容易判错的情形（都由上面的顺序决定）**：
- Δ 显著为正，但整个 CI 都在 SESOI 以下（例如 [0.005, 0.015]，p < α）→ **不成立**，因为第 3 步排在第 4 步之前。代码的说法是：LLM 确实有增量，但小于最小关注效应。
- Δ 已经过线，但保留率 CI 上界 < min_retention → **不成立**。
- 未控制混淆，同时 P1 也不过 → **无法判定**，因为第 1 步排在封顶之前。例：S1 走 ② 路径（附录 A）。
- S1 走 ① 路径：P1–P5 全过，混淆已控制，nested 选层；Δ = 0.049，CI [−0.004, 0.098]，p_null = 0.0432。第 3 步不成立：0.098 ≥ 0.02，且 min_retention 为 null。第 4 步也不成立：CI 下界 −0.004 ≤ 0。所以是 **无法判定（证据不足）**。注册表里 S1 的判定就出自 ① 路径。

### 5.4 min_retention 规则（默认 null）

- 默认 null：只报告保留率（r_LLM / reference_value）及其 CI，**不进判定**——这是明示、可审计的状态（行内 `claim_scope` 写「未设 min_retention，保留率不进判定」）。
- 只有同时满足以下四条，才能给某条 claim 设数值：① 声称本身是定量的（原文给出一个要复现的幅度）；② `reference_value > 0`（=0 会触发 `judge.py` 除零后 None 比较抛错；为负会使 CI 上下界颠倒，RSA 类负值指标不能这样用）；③ `reference_metric` 与本管线 metric 同口径，或已有同口径重算的参考值（S1 目前不满足）；④ 数值在运行**之前**提交（claim 配置所在 commit 早于判定行的 `timestamp`，可用 `git_commit`/`config_sha256` 核对）。
- 取值：无原文精度信息时用 0.5 并标「约定值，非统计推导」；有原文 n/SE 时优先按 small telescopes 思路用原文精度计算。
- 不管设不设，都要报告 `retention` 及 `retention_ci_lo/hi`（`reference_value` 为 null 时记 N/A），并写出翻转阈值：门槛 > `retention_ci_hi` → 定量部分不成立；门槛 ≤ `retention_ci_lo` → 定量部分过线（S1：0.534 / 0.159），第三方可代入自己的门槛。
- 注：`claim.reference_ceiling` 目前既不进判定也不进行（`ROW_FIELDS` 无此列），只在 manifest 的 config 里出现。

> 注意「保留率」= r_LLM / reference_value（论文报告值还剩几成），**不是** r / ceiling（归一化预测力）——后者是另一件事，见坑 #3。reference_value 取哪个数见第 4 步。

## 审计中已确认的坑（评审者要主动查，不依赖作者声明）

1. **切分欠报是系统性字段欠报**：时序对齐声称（ECoG/fMRI 叙事或连续刺激）常见「10 折/5 折 CV」却不写 contiguous 还是 shuffled——本审计 S1/T1/C1 三篇同属此坑，E1 是显式 contiguous 的反例。
2. **层选择**：已升级为 3.6 的正式规则，① 只认 nested 或事先登记的 fixed；② 分 L-a / L-b / L-c 三类，只有 L-c 封顶。评审者要主动查原文**有没有**选层对照，不能默认「原文没提」。S1 就是有对照的例子（L-b）。
3. **归一化与口径陷阱**：r/ceiling 不能直接给归一化预测力——读出/聚合口径不同（岭 vs OLS、体素中位数 vs 均值、留出被试 vs split-half）时须先同口径重算 ceiling。v0.3 补充：**保留率 r_LLM / reference_value 也受同样影响**，不只是 r/ceiling。实测：同一次 S1 运行里，本管线自己的 shuffled 对照 r_LLM = 0.409，比原文的 0.31 还高。可见光是口径不同（读出、聚合、层选择）就能改变数字。因此 `reference_metric` 的五项口径只要有一项不同，保留率就只报告不判定（5.4 条件 ③）。
4. **口径叠加**：换 contiguous 后同时改 pooling/层选择时，「r 掉了多少」不能全记在切分账上——切分 + 层选择叠加，须逐项拆分。
